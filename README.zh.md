# dsh-flow-queue

给 DSH 的可视化流程图，就在右侧栏里。把 **提示词、切换模型、执行命令、条件分支、循环、断点** 画成一张有向图，按连线顺序执行，并且**只在轮次边界执行**。

English: [README.md](README.md)

## 它修的是什么问题

DSH 里 `/model` 是立刻生效的：一轮还在跑（或正在等断联重试）时切模型，重试会按新模型重发，于是「这一轮」被悄悄换掉。

本插件把模型切换、提示词投递、命令执行全部变成**图中的节点**，只在 `turn/end` 落盘、且该会话 Agent 空闲时才推进。所以：

- 在途请求与它的每一次重试，始终保持它开始时的模型；
- 切换只发生在两轮之间——正好是「下一个输入之前」；
- 图上的顺序＝执行顺序，跑到哪一步、结果如何，画布上实时可见。

## 界面

插件只往右侧栏注册一个「流程队列」标签页，**整张画布就在这个标签页里**，不弹独立窗口：

- **顶部**：运行状态、开始/暂停/继续/停止、⋯ 菜单（自动排版、流程包、重置、清空）。
- **第二行**：`+提示词` `+切换模型` `+执行命令` `+条件分支` `+循环` `+断点`，点一下加到画布。
- **画布**：拖动卡片摆位；从右侧圆点拖到另一个卡片即可连线（分支/循环有「是/否」「再循环/退出循环」两个圆点）；点连线断开；空白处拖动可平移，右下角 −/+/⤢ 控制缩放。
- **选中一个步骤**：画布区域切换成该步骤的检查器（左上角 ← 返回），按类型给字段，表头提供「从此步开始」「删除」。
- **流程包**：⋯ → 流程包，在同一个面板里保存/载入/删除。

右侧栏窄，所以自动排版是自上而下的单列蛇形（每步一行），节点宽度按窄栏缩到 196px；往右可以自由拖开。

## 步骤类型

| 类型 | 做什么 | 输出 |
|---|---|---|
| 提示词 | 投递一条用户消息（可带图片与文件附件；可单独指定这一步用的模型） | 下一步 |
| 切换模型 | 在本轮边界把会话切到指定模型 | 下一步 |
| 执行命令 | 运行一个斜杠命令（`/compact`、`/plan` 等，走 `commands.execute`） | 下一步 |
| 条件分支 | 按条件选「是 / 否」两条路 | 是 / 否 |
| 循环 | 满足退出条件或到达最多轮数时走「退出循环」，否则走「再循环」 | 再循环 / 退出循环 |
| 断点 | 停下等人按「继续」 | 下一步 |

### 条件怎么判

条件对**最近一次产出**求值（提示词节点看该轮助手输出的文本与工具失败记录；命令节点看命令结果）：

- `总是成立`
- `正则匹配上一轮输出`（多行模式）
- `包含文本`
- `包含完成标记`（默认 `[[FLOW:DONE]]`，可在提示词里要求模型完成时输出它）
- `上一轮有工具失败`（该轮出现过 `tool/result` 的错误）
- `上一步失败`（命令失败，或该轮以 error/aborted 结束）
- 每条都可「取反」

### 提示词块能带什么

- 多行文本；
- 图片附件（读为 base64，经宿主 `attachments.saveImages` 落盘后作为 `image` content part 发出）；
- 任意文件附件（`attachments.admitEncodedFile` → `file` content part）；
- 这一步专用的模型（留空＝沿用当前）。

**已知差别**：`@路径` 由原生输入框在提交时展开，图编辑器不走那条路径，所以 `@` 只会当普通文本发出；要附带文件内容请用「添加附件」。图片/文件单步最多 8 个。

## 运行状态

`未运行 / 运行中 / 等待继续（断点） / 已暂停 / 已完成 / 出错`。每个步骤卡片显示状态、耗时、实际服务它的模型（取自该轮 `request/header`）、错误与命令结果。

- **不会有幽灵成功**：轮次以 error/aborted/interrupted 结束时，该步记失败。
- **不会卡死**：提示词被接受但 30 秒内没有新轮次 → 该步 `no-turn` 失败、整轮标记出错。
- **重启安全**：进程重启时仍标记为执行中的步骤显示为 `interrupted`，运行状态转为「已暂停」，不会自己偷偷接着跑。
- 编辑图必须在不运行的时候；运行中点「暂停/停止」再改。

## 流程包（跨会话复用）

⋯ → 流程包可把当前图存成流程包（`$DSH_PROFILE_DIR/flow-queue/packages/*.json`），在任意会话里载入、删除。存的是节点与连线，不含运行状态。

## 安装

```sh
dsh plugin --profile web add github:Eclipse-NotFound/dsh-flow-queue
```

装完重启 Harness web 运行时（bundle 在启动时组装），再刷新页面。需要 DSH `>=0.2.1-rc.1 <0.3.0`。

插件在同源下注册 `/flow-queue/api/…` 路由，全部经 `ctx.connection.requestRejection` 准入，只有已认证的页面能调用；只保存你自己创建的内容（每会话的图与流程包目录），不向任何地方发送数据。

## 接口（宿主半）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/flow-queue/api/state?sessionId=…` | 图 + 运行快照 |
| GET | `/flow-queue/api/models` | 可路由模型目录 |
| GET | `/flow-queue/api/packages` | 流程包列表 |
| POST | `/flow-queue/api/command` | 图/运行/附件变更 |
| POST | `/flow-queue/api/packages` | `save` / `load` / `delete` |

命令 `op`：`node.add` `node.update` `node.remove` `node.attach` `node.detach` `edge.add` `edge.remove` `entry.set` `graph.clear` `graph.reset` `run.start` `run.pause` `run.resume` `run.stop` `run.from`。

## 开发

```sh
node --check client.js
node --check host2.js
node test/offline-check.mjs   # 8 个场景：边界守卫、分支、循环（含熔断）、断点、命令块、附件、流程包、校验
```

测试用模拟的 Cordis 上下文驱动真实宿主模块，不需要 DSH 进程。

### 宿主代码热更新

运行中的 Harness 按解析后的 URL 缓存已导入的模块，所以改 `hostN.js` 不会自动生效。更新步骤：

1. 改完后另存为下一个版本文件（`host3.js`），同步改 `index.js` 的 re-export 与 `cordis.patch.yml` 的行名（`dsh-flow-queue/host3`）；
2. 用插件管理器把本 bundle 关一次再开（或重启应用）。

`client.js` 不需要这套：页面侧会重新取客户端包，刷新页面即可。
