# dsh-flow-queue

给 DSH 的可视化流程图，就在右侧栏里。把 **提示词、切换模型、执行命令、条件分支、循环、断点、子代理扇出、跨会话发送/等待** 画成一张有向图，按连线顺序执行，并且**只在轮次边界执行**；其上再叠一层**编制视图**管理工作区里协作的会话。

English: [README.md](README.md)

## 它修的是什么问题

DSH 里 `/model` 是立刻生效的：一轮还在跑（或正在等断联重试）时切模型，重试会按新模型重发，于是「这一轮」被悄悄换掉。

本插件把模型切换、提示词投递、命令执行全部变成**图中的节点**，只在 `turn/end` 落盘、且该会话 Agent 空闲时才推进。所以：

- 在途请求与它的每一次重试，始终保持它开始时的模型；
- 切换只发生在两轮之间——正好是「下一个输入之前」；
- 图上的顺序＝执行顺序，跑到哪一步、结果如何，画布上实时可见。

## 界面

插件只往右侧栏注册一个「流程队列」标签页，**整张画布就在这个标签页里**，不弹独立窗口：

- **顶部**：运行状态、开始/暂停/继续/停止、⋯ 菜单（自动排版、流程包、重置、清空）。
- **第二行**：`+提示词` `+切换模型` `+执行命令` `+条件分支` `+循环` `+断点`，点一下加到画布。
- **画布**：拖动卡片摆位；从右侧圆点拖到另一个卡片即可连线（分支/循环有「是/否」「再循环/退出循环」两个圆点）；点连线断开；空白处拖动可平移，右下角 −/+/⤢ 控制缩放。
- **选中一个步骤**：单击（按下后没有移动）会在画布下方打开该步骤的检查器抽屉——画布不换页，拖动因此不会被打断；抽屉表头有「从此步开始」「删除」，点 ↓ 收起。
- **流程包**：⋯ → 流程包，在同一个面板里保存/载入/删除。

两个入口可以打开它：左侧栏底部设置旁的图标，以及右侧栏开始页里的「流程队列」卡片。那个开始页给每种标签页排一张卡片、溢出直接裁掉而不滚动，装得插件多了最后几张（包括「更多工具」）就点不到；本插件自己的那张卡片会向上找到真正裁剪内容的容器，在挂载期间把滚动打开（卸载时还原原来的行内样式）。

右侧栏窄，所以自动排版是自上而下的单列蛇形（每步一行），节点宽度按窄栏缩到 196px；往右可以自由拖开。

## 步骤类型

| 类型 | 做什么 | 输出 |
|---|---|---|
| 提示词 | 投递一条用户消息（可带图片与文件附件；可单独指定这一步用的模型） | 下一步 |
| 切换模型 | 在本轮边界把会话切到指定模型；模型声明了思考强度档位时可一并指定 | 下一步 |
| 执行命令 | 运行一个斜杠命令（`/compact`、`/plan` 等，走 `commands.execute`） | 下一步 |
| 条件分支 | 按条件选「是 / 否」两条路 | 是 / 否 |
| 循环 | 满足退出条件或到达最多轮数时走「退出循环」，否则走「再循环」 | 再循环 / 退出循环 |
| 断点 | 停下等人按「继续」 | 下一步 |
| 扇出子代理 | 把同一条提示词发给最多 8 个一次性子代理（`spawn` 后端），每路可强制自己的模型/强度，留空则沿用会话路由；收齐后把每路产出聚合成流程产出。聚合方式：全部完成 / 前 k 个完成（够了就取消慢的）/ 首个完成。父轮次不受影响，扇出是**在轮次边界旁边等**，不是跨过它 | 下一步 |
| 发送消息 | 把一条消息投给编制里的另一个会话（先落盘、退避重试、同目标严格保序；死信挡住队列直到人工重试）。可附带本会话本轮改动的文件清单（仅文件工具写入，盲区如实标注） | 下一步 |
| 等待会话 | 等目标在等待开始后完成一轮并空闲，或等目标最近一轮输出包含标记（默认 `[[FLOW:REPORT`） | 下一步 |

### 条件怎么判

条件对**最近一次产出**求值（提示词节点看该轮助手输出的文本与工具失败记录；命令节点看命令结果）：

- `总是成立`
- `正则匹配上一轮输出`（多行模式）
- `包含文本`
- `包含完成标记`（默认 `[[FLOW:DONE]]`，可在提示词里要求模型完成时输出它）
- `上一轮有工具失败`（该轮出现过 `tool/result` 的错误）
- `上一步失败`（命令失败，或该轮以 error/aborted 结束）
- `模型判断`（**自然语言条件**，如「卡顿降到 10ms 以下」）：执行到该步时发起**一次**极简判定轮——指令约 40 token＋条件原文，要求模型用最便宜的核查后**首行只答 YES 或 NO**，引擎解析首行决定走向，卡片显示判定与理由摘要；答不出 YES/NO 判该步失败（`no-decision`）。不注册全局工具、不改任何会话的工具表；循环里每一轮都重新判定，不复用旧结论。
- 每条都可「取反」

### 提示词块能带什么

- 多行文本；
- 图片附件（读为 base64，经宿主 `attachments.saveImages` 落盘后作为 `image` content part 发出）；
- 任意文件附件（`attachments.admitEncodedFile` → `file` content part）；
- 这一步专用的模型（留空＝沿用当前）。

**`/` 命令与技能、`@` 文件引用**：提示词编辑框沿用了输入框的两个习惯——

- 行首输入 `/` 弹出该会话可用的**命令**（宿主命令，如 `/compact`）与**技能**目录，↑↓ 选择、Enter/Tab 确认、Esc 关闭；选中命令插入 `/name `，选中技能插入「使用技能 <name>：」，由模型按目录装载。
- 输入 `@` 弹出**工作区文件引用**（`@path` 语义与原生一致：引用路径不注入内容，模型自行读取）；选目录会带上 `/` 继续往下选。
- **整段文本恰好是一行宿主命令**（如只写 `/compact`）的提示词步骤，执行时按命令运行而不是发给模型——与输入框「命令行绝不静默降级为普通提示词」的规则一致；多行文本或未知命令仍按普通提示词投递。
- 只有客户端弹窗的命令（如没有宿主命令行的 `/model` 选择器）不出现在 `/` 菜单里，也不会被内联执行。

**已知差别**：`@路径` 是文本引用而非内容注入——要附带文件内容请用「添加附件」。图片/文件单步最多 8 个。

## 运行状态

`未运行 / 运行中 / 等待继续（断点） / 已暂停 / 已完成 / 出错`。每个步骤卡片显示状态、耗时、实际服务它的模型（取自该轮 `request/header`）、错误与命令结果。

- **不会有幽灵成功**：轮次以 error/aborted/interrupted 结束时，该步记失败。
- **不会卡死**：提示词被接受但 30 秒内没有新轮次 → 该步 `no-turn` 失败、整轮标记出错。
- **重启安全**：进程重启时仍标记为执行中的步骤显示为 `interrupted`，运行状态转为「已暂停」，不会自己偷偷接着跑。
- 编辑图必须在不运行的时候；运行中点「暂停/停止」再改。

## 流程包（跨会话复用）

⋯ → 流程包可把当前图存成流程包（`$DSH_PROFILE_DIR/flow-queue/packages/*.json`），在任意会话里载入、删除。存的是节点与连线，不含运行状态。

## 安装

```sh
dsh plugin --profile web add github:Eclipse-NotFound/dsh-flow-queue
```

装完重启 Harness web 运行时（bundle 在启动时组装），再刷新页面。需要 DSH `>=0.2.1-rc.1 <0.3.0`。

插件在同源下注册 `/flow-queue/api/…` 路由，全部经 `ctx.connection.requestRejection` 准入，只有已认证的页面能调用；只保存你自己创建的内容（每会话的图与流程包目录），不向任何地方发送数据。

## 接口（宿主半）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/flow-queue/api/state?sessionId=…` | 图 + 运行快照 |
| GET | `/flow-queue/api/models` | 可路由模型目录 |
| GET | `/flow-queue/api/packages` | 流程包列表 |
| POST | `/flow-queue/api/command` | 图/运行/附件变更 |
| POST | `/flow-queue/api/packages` | `save` / `load` / `delete` |

命令 `op`：`node.add` `node.update` `node.remove` `node.attach` `node.detach` `edge.add` `edge.remove` `entry.set` `graph.clear` `graph.reset` `run.start` `run.pause` `run.resume` `run.stop` `run.from`。

## 开发

```sh
node --check client.js
node --check index.js
node test/offline-check.mjs      # 宿主模块 + 模拟 Cordis 上下文
node test/client-apply-check.mjs # 客户端激活 + 模拟模块加载器/上下文
```

宿主检查跑 22 个场景：边界守卫、分支、循环（含熔断）、断点、命令块、附件、流程包、校验、提及目录与整行命令、自然语言判定、扇出聚合（含一路失败）、k-of-n 提前收并取消慢的、扇出超时、停止取消扇出、循环内每轮重扇出、outbox 投递与编制 CRUD、退避→死信挡队→复活按序送达、等待空闲、等待标记、跳数上限与改动归因块、停整队幂等、内置报告协议包。客户端检查模拟浏览器模块加载器，确认 `apply` 注册了标签类型、标签主体与侧栏入口。

### 更新已安装的插件

宿主半每个进程只加载一次，所以改宿主需要把 bundle 关一次再开（或重启应用）。客户端半由页面重新下载，刷新页面即可——但**行名必须写包名本身**（`name: dsh-flow-queue`）：写成子路径（`dsh-flow-queue/host2`）会给客户端模块系统一个 bundle 从未注册的行 id，整个客户端半会静默地不加载。
